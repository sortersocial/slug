# Error: Actor Not Detected During Ingest

**Date:** 2026-01-11
**Status:** Unresolved
**Context:** After refactoring to single-event model (Ingest only)

## Problem

When attempting to ingest `slug-social-archive/whitepaper.sorter`, the server returns:
```
Error: server error: ingest requires @actor declaration

hint:
add `@yourname` at the start of your document
```

## The File Contains An Actor

`whitepaper.sorter` line 3:
```
@aec1e31c:claudecode:anthropic/claude-sonnet-4.5
```

This actor declaration EXISTS in the file but is not being detected.

## Possible Causes

### 1. DSL Parser Not Recognizing Format
The actor line uses the OLD identity format:
- Old: `@<rig>:<model>:<uuid-prefix>`
- New: `@<uuid>:<rig>:<model>`

The DSL parser might not be extracting this as an Actor statement.

### 2. Format Validation Failing Silently
The validation checks for:
```rust
// Full format must be: <uuid>:<rig>:<model>
let parts: Vec<&str> = actor.split(':').collect();
if parts.len() != 3 {
    return Err(...);
}
```

For `@aec1e31c:claudecode:anthropic/claude-sonnet-4.5`:
- Parts: `["aec1e31c", "claudecode", "anthropic/claude-sonnet-4.5"]`
- Count: 3 ✓
- But `aec1e31c` is NOT a full UUID

The UUID validation should fail:
```rust
if uuid::Uuid::parse_str(uuid_part).is_err() {
    return Err(format!("Invalid UUID..."));
}
```

But the error we see is "ingest requires @actor declaration", not "invalid actor format".

## Expected Error vs Actual Error

**Expected:** "Invalid UUID in actor format: 'aec1e31c' is not a valid UUID..."
**Actual:** "ingest requires @actor declaration"

This suggests the validation isn't running, which means the DSL parser isn't finding the Actor statement.

## Code Flow

```rust
// Parse once for validation and metadata extraction.
for s in &doc.statements {
    match s {
        dsl::Stmt::Actor { name } => {
            // Validate actor format.
            if let Err(msg) = validate_actor_format(&name) {
                return api_error(StatusCode::BAD_REQUEST, "invalid actor format", Some(msg));
            }
            let a = canonicalize_actor(&name);
            current_actor = Some(a.clone());
            voter_key_id = a;
        }
        // ... other statements
    }
}

// Require actor for threading/notifications.
let Some(actor) = current_actor.clone() else {
    return api_error(
        StatusCode::BAD_REQUEST,
        "ingest requires @actor declaration",
        Some("add `@yourname` at the start of your document".to_string()),
    );
};
```

If the Actor statement was found and validation failed, we'd error with "invalid actor format".
Since we're erroring with "ingest requires @actor declaration", the Actor statement was never found.
