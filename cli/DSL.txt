SLUG DSL REFERENCE

The Slug DSL mixes freeform prose with structured statements. Statements start with specific characters (`#`, `@`, `/`, `~`, `h`). Everything else is Prose.

```sorter
@some-user-identity
#review: My Review Thread

prose blocks which are the body of the OP post...
Blank lines are preserved to maintain paragraph structure.

~/item/a {itembody}
/python { A high-level scripting language }

~/item/a > /python { Item A is better because of X. }
/python 3:1 /go { Python's ecosystem is much richer than Go's. }
https://example.com/lang = /go { They are equally good in this context. }
```

SYNTAX RULES

```sorter
@<identity>
```
Declares the author. Must be ASCII, no whitespace.

```sorter
#<tag>
#<tag>: <subtitle>
```
Starts a thread. Tag allows alphanumeric, `-`, `_`, and `/`. Subtitle max 100 chars.

```sorter
/<global-item-path> { description }
~/<namespaced-item-path> { description }
```
Defines an item. Paths can be nested (e.g. `~/category/item`). 
Descriptions (bodies) are wrapped in `{}` and can be adjacent (e.g. `/arrived{ready}`).

```sorter
https://example.com/item { description }
```

URLs can be used directly as items in definitions or votes.
Canonicalization rules for URLs:
- `~/` and `https://slug.social/~/` map to the same local item path.

```sorter
<item1> <comparison> <item2> { required explanation }
```
Compares two items. The explanation is REQUIRED.
Comparisons:
- `>` (Left is better, 2:1)
- `<` (Right is better, 1:2)
- `=` (Equal, 1:1)
- `X:Y` (Custom ratio, e.g. `3:1`, `0:0`)

BLOCK MASKING (ESCAPING)

When writing bodies or explanations, you can use braces `{}` and code blocks without breaking the parser. The parser protects blocks in this hierarchy:
1. Code fences: ``` ... ```
2. Double braces: {{ ... }}
3. Single braces: { ... }

```sorter
/code { Here is a block: ```def foo(): return {"a": 1}``` }
```
